# SR6 S0 — Game picker and per-game split (Chummer 0.9.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app opens on a game picker (Shadowrun Anarchy 2.0 / Shadowrun 6th World), remembers the choice per browser and offers a switch in every header. The server keeps each game's runners, NPCs, campaigns and trash apart and refuses the other game's files. Anarchy works exactly as in 0.8.3 at the same paths and routes, and existing data keeps working with no migration. The SR6 side is only a shell for now: an empty "Your runners" page ("SR6 builder coming") and a Books page that the core rulebook import (S1) will use. There are no SR6 rules yet.

**Architecture:** One ruleset table (`server/games.mjs`: `ca2` and `sr6`, each with its character root tag, namespace and sub-folder) drives one store factory in `server.mjs`. The factory runs once with Anarchy's dirs, which are today's dirs unchanged. It runs again with `characters/sr6/` and `custom/sr6/`. Anarchy keeps the unprefixed `/api/*` routes byte for byte. SR6 uses the same routes under `/api/sr6/*`. The dispatcher strips the prefix and passes the request to the SR6 instance, which reads only `sr6/` folders and accepts only `sr6:character` roots. `sr6` is reserved as an account name and as a book id, so no Anarchy listing (accounts' folders, Library books, the importer's library walks) can ever reach an `sr6/` folder. The client takes the game from the hash: `#/sr6/...` is SR6 and everything else is Anarchy as today. `localStorage['chummer.game']` stores the last pick or switch, and it chooses where a bare `#/` lands.

**Tech Stack:** as the repo already uses (TS/React/Vitest/Playwright/Node server, no dependencies; Python importer).

**Spec:** `docs/superpowers/specs/2026-10-02-sr6-ruleset-design.md` (§1 "Game separation", "Game picker"; §2; §6 S0; §7 "Game separation is enforced by the server"). Rulings the spec left open are marked (R).

## Global Constraints

- Ruleset ids `ca2` | `sr6`. `server/games.mjs` (new, no imports) exports `GAMES = { ca2: { id, tag: 'ca2:character', ns: 'urn:chummer-anarchy2:character:1', sub: '' }, sr6: { id, tag: 'sr6:character', ns: 'urn:chummer-sr6:character:1', sub: 'sr6' } }`, `RESERVED = ['sr6']` and `scoped(path) → { game, path }` (`/api/sr6` or `/api/sr6/...` → `sr6` and the path with `/api` in place of `/api/sr6`; anything else → `ca2`, path unchanged).
- Layout (R): Anarchy stays at `characters/<user>/`, `characters/.npcs/`, `characters/.compendiums/`, `characters/.trash/`, `custom/` (campaigns.xml, imported/, edits/, samples/, table-rules.xml) and `library/<book>/`, with no move or rename. SR6 uses the same shape one level down: `characters/sr6/<user>/` (+ `.trash/`), `characters/sr6/.npcs/<user>/`, `characters/sr6/.trash/`, `custom/sr6/campaigns.xml`, and later `custom/sr6/imported|edits/` and `library/sr6/<book>/` (S1). Platform files stay shared: `library/.config/` (accounts, sessions, sign-in, AI settings and keys), `library/backgrounds/` and `library/.backups/`. Display settings (`ca2.settings.v1`) stay per browser and shared (R): they hold theme and print style, not game data.
- API (R): a path prefix, not a header. It shows up in logs and links (backup downloads, `<a href>`) and needs no client fetch rewriting. The unprefixed data routes are Anarchy's and stay byte-for-byte unchanged. In S0, `/api/sr6/` serves `characters`, `npcs`, `trash`, `npcs/trash` and `campaigns` (with the same shapes and rules). Every other `/api/sr6/...` path answers 404 until its release adds it (books S1, edits/table-rules/samples/ask S1–S2, compendiums S4). Platform routes (`health`, `auth`, `setup`, `users`, `auth-settings`, `backgrounds`, `ai-*`, `backup`, `restore`, `datapack`) exist unprefixed only. `need()` checks the role of a scoped path as if it had no prefix.
- Cross-game refusal: a PUT to a game's character or NPC store must carry that game's root and namespace. An Anarchy body sent to `/api/sr6/*` gets 400, and an SR6 body sent to `/api/*` gets 400, which today's `NS` check already does. A trash restore refuses a file of the other game (400). A campaign only sees its own game's runners and NPCs, so an id from the other game gets 404, and a campaign id from the other game also gets 404 because each game has its own `campaigns.xml`.
- SR6 file root in S0 (R): `<sr6:character xmlns:sr6="urn:chummer-sr6:character:1" formatVersion="1" id="…" …>`. The server relies only on `id`, `rev`, `campaign`, `streetName`/`name` and `updatedAt`, plus a leading `<npc>` child for NPCs, exactly as for Anarchy. S2 defines the rest of the format and its XSD. Tests use made-up minimal files.
- Reserved name (R): `sr6` can't be a new username or a rename target (400, checked case-insensitively in `fields()`, which setup, create and rename all use). It can't be a book id either (`BOOK_ID` excludes it). An account named `sr6` loaded from an older `users.xml` still signs in and keeps its Anarchy runners at `characters/sr6/*.xml`. While it exists, every `/api/sr6/*` route answers 409 "rename the account sr6 first" and no SR6 folder is written. After the rename, its runners move to `characters/<new>/` as for any rename.
- Accounts span both games (R): a rename moves both games' folders and both games' campaign memberships. A delete retires both games' folders, each into its own game's trash. `runners.count` (the Users list and "still has runners") counts both games. `adopt` (pre-accounts upgrade) and `move` (admin moves a runner) stay Anarchy only in S0.
- Client game choice (R): the picker is the first screen, shown before setup and sign-in when the hash is empty and nothing is stored. The order is Loading → `#/setup/reset` (Recover link) → picker → setup → sign-in → app. A deep link (`#/c/<id>`, `#/sr6/...`) opens its own game without the picker. A pick or a header switch stores the choice and goes to that game's home (`#/` or `#/sr6`). A bare `#/` with `sr6` stored is replaced with `#/sr6`. Browser-mode (no server) SR6 keys are reserved as `sr6.library.v1` and `sr6.npcs.v1` for S2, and nothing uses them yet. Anarchy's keys (`ca2.library.v1`, `ca2.npcs.v1`, `ca2.library.sort`, `ca2.settings.v1`) are unchanged.
- Backup (R): no code change. The existing zip of `characters/`, `custom/` and `library/` already holds `sr6/`, and restore replaces all three folders. Tests prove it.
- Anarchy changes are limited to the switch: the header gains one switch icon and the Brand stays "Chummer **Anarchy** 2.0". Every existing Vitest, Python and Playwright suite passes unchanged, except the one-line `storageState` change in Task 5.
- Branch `feat/0.9.0` from origin/main after this plan's docs merge; the controller merges and releases. Never touch `public/data/*.xml`, `public/custom/`, `custom/`, `library/` or `.extract/private`. No book text in tests. Never kill processes by image name.
