# Foundry importer 0.4.0 (default icons) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The importer ships icons and points every imported item, vehicle and metatype at the best one: a book-specific file, else a by-name file, else the sub-kind default, else the category default; an "Apply icons" button in the module settings re-applies them; art a user chose is never overwritten.

**Architecture:** Icons live in the module under `icons/` with a generated `icons/index.json` (Foundry can't list module files cheaply). A pure `iconFor(key, name, bookId, index)` picks the path; the translator stores the entry's icon key in its flags and sets `img`; a settings menu (ApplicationV2) runs "Apply icons" over world documents and the module's compendiums, replacing only images that are empty, a stock default (Foundry's or sra2's), or already the module's.

**Tech Stack:** plain ES modules; Vitest; a Node build tool using `sharp` (dev dependency) to make the icons; Foundry V14.

**Spec:** decisions in conversation 2026-10-01/02 (owner): ship art in the module; defaults per category and sub-kind, specific art by item name (same name = same icon), optional book-specific file; replace only images that point at the module's art or at sra2/Foundry defaults; characters get a portrait AND a token, separately (later release); the default-icon choices approved from the owner's sheets.
