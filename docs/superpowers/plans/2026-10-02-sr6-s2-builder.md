# SR6 S2 — SR6 runner model, creation engine (five methods), editor, Review, print Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A player on the Shadowrun 6 side makes a runner with any of the five creation methods (priority, sum-to-ten, point buy, karma, lifepath), edits it on the tabs Concept, Creation method, Attributes, Skills, Qualities, Magic or Resonance, Augmentations, Gear, Vehicles, Contacts & lifestyle and Review, sees every budget itemized and every broken rule with its page, finalizes it, prints it on an SR6 sheet, and exports or imports its file. The SR6 runners page replaces S0's empty state. The S0 review leftovers are fixed: SR6 Trash and Users links open SR6 pages, and an account whose only runners are SR6 ones can have them moved and can be deleted.

**Architecture:** One runner = one XML file (`<sr6:character xmlns:sr6="urn:chummer-sr6:character:1">`, `public/data/sr6/schema/character.xsd`) in S0's `/api/sr6/characters` store, read and written by `src/sr6/engine/charxml.ts` (Anarchy's helpers reused). The engine is a TypeScript port of SR6 Forge's pure creation code (`providers.mjs`, `budgets.mjs`, `rules.mjs`, `ChargenEngine.spend`), fed by two inputs instead of Forge's `chargen-data.json` + `creation-rules.json`: typed views over the S1 catalog (`src/sr6/engine/data.ts`), and the table's creation rules (`custom/sr6/creation.xml`, `src/sr6/engine/creation.ts`), which hold every rule number the book prints only in prose, filled in once by the admin from their own book. Derived values are formulas in code (`src/sr6/engine/derive.ts`). The UI reuses the Anarchy editor's save, conflict and undo machinery (moved into `src/ui/useAutosave.ts`), the repo (made generic over a codec), the portrait/token editor, the sheet art and the print page.

**Tech Stack:** as the repo already uses (TS/React/Vitest/Playwright/Node server, xmllint-wasm for XSD tests, no new dependencies). No Python in S2.

**Spec:** `docs/superpowers/specs/2026-10-02-sr6-ruleset-design.md` (§1 "Creation methods", "Game separation"; §2; §4 Builder except Ledger, NPCs and Compendiums; §6 S2; §7). Builds on S0 (`docs/superpowers/plans/2026-10-02-sr6-s0-picker-split.md`) and S1 (`docs/superpowers/plans/2026-10-02-sr6-s1-core-import.md`, all tasks done first: S2 consumes S1 Task 8's `Sr6Catalog`/`loadSr6Catalog`/`buildSr6Catalog`, Task 7's `/custom/sr6/` route and Task 9's `Sr6App` routes and `src/sr6/ui/Data.tsx`). Rulings the spec left open are marked (R).

## Review Focus

- A catalog entry a runner uses is gone or renamed (re-import, catalog edit, book removed): the runner still opens and prints; the line shows its snapshot or its stored name, and Review has an error "<name> is no longer in the catalog" (Task 3 + Task 6 tests).
- The creation rules are empty or half filled (a fresh install, a new table): the builder opens; each method lists the settings it still needs and can't be picked until they're set; a rule whose setting is unset is skipped and Review warns "<setting> isn't set: Game data → Creation rules" (Task 2 + Task 6 tests).
- A book value the engine can't read (`12x`, `Rating × ?`, an AR of `9/x`): never NaN in a total; the item counts 0, and Review warns with the entry's name and page (Task 4 tests).
- The player switches method or priority letters mid-build: spends that still mean something stay, budgets recompute, a metatype or magic path no longer legal is cleared, nothing throws (Task 7 tests).
- A file from the other game is imported, or saved to the wrong store: the SR6 runners page refuses an Anarchy runner and the Anarchy page an SR6 one, each saying where it belongs (Task 3 + Task 11 tests); the server already refuses the wrong root (S0).
