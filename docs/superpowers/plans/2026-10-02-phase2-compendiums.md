# Phase 2 — User compendiums (Chummer 0.8.0, importer module 0.6.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GMs and the admin make named compendiums of their own amps, weapons, armor, gear, spells, complex forms, vehicles and NPCs/critters, share them (private / a campaign's GMs / the table), browse the books as read-only compendiums, copy book entries in, move NPCs in, and export a compendium for Foundry like a book; the module imports it as its own compendium folder.

**Architecture:** A compendium is one data-format file (`<ca2:data kind="compendium">`) whose root names it and its own source id; its children are ordinary `<amp>`, `<item>`, `<vehicle>` entries plus embedded `<ca2:character>` NPCs. The server keeps it under `charDir/.compendiums/<owner>/<id>.xml`, served only by an editor-gated `/api/compendiums` with the NPC store's rev/If-Match rules. The client loads the compendiums a GM can read into that GM's catalog as one more overlay (`buildCatalog` learns kind `compendium`, origin `user` → "House"), so the existing pickers, the edit form and `exportBooks` work on them unchanged. Phase 3 only has to hand the same files to players.

**Tech Stack:** as the repos already use (TS/React/Vitest/Playwright/Node server, no dependencies; module ES modules/Vitest/Quench).

**Spec:** `docs/superpowers/specs/2026-10-02-npcs-and-compendiums-design.md` (§1 "Compendiums (phase 2)", §2). Rulings the spec left open are marked (R).

## Global Constraints

- File (R): `<ca2:data xmlns:ca2="urn:chummer-anarchy2:data:1" kind="compendium" version="1" id="<12 hex>" name="…" source="<SOURCE_ID>" sharing="private|campaign|table" campaign="<12 hex, only when sharing=campaign>" rev="n" updatedAt="ISO">`; children in any order: `<amp>`, `<item>` (kind gear/weapon/armor/spell/complex-form), `<vehicle>` (common.xsd's types, every entry `source` = the compendium's source, its own text in `<narrative>`/`<text>`), and NPCs as `<ca2:character xmlns:ca2="urn:chummer-anarchy2:character:1" …>` exactly as `characterToXml` writes them (must have `<npc>`). Schema `public/data/schema/compendium.xsd`. The owner is the folder, never the file.
- Source id (R): chosen at creation, `SOURCE_ID` (`/^[A-Z][A-Z0-9-]{0,19}$/`, books.mjs), fixed afterwards, unique across every compendium on the server and every source in `public/data/sources.xml`, `custom/imported/sources.xml`, `custom/sources.xml`, `custom/edits/sources.xml` (server 409). Entry ids `<source lowercased>.<slug>[-n]` (EditEntry's `newId`). In the catalog the source is `{ id, name, publisher: owner's name, canon: false, origin: 'user' }`, so it shows "House"/Non-canon like other house content.
- Access (R): `need('/api/compendiums*') = 'editor'`. Read: the owner; the admin (all); an editor: `sharing=table` ones, and `sharing=campaign` ones whose campaign both they and the owner GM (`campaigns.leads`). Write/delete: the owner only (403 otherwise, admin included, as for NPCs). Players: 403 on every route in this phase (phase 3 adds a player-readable list of table/campaign-shared entries; nothing here may assume players never read the format).
- Store (R): `charDir/.compendiums/<owner>/` (dot folder; backups include it as part of `characters/`); DELETE moves the file to `.compendiums/<owner>/.trash/<file>-<ms>.xml` (no restore page this phase: the admin restores on disk). Account rename moves it, account delete retires it to `.compendiums/.trash/<user>-…`, a new account refuses an existing folder (409) — the same three hooks as `.npcs`.
- Body cap (R): 20 MB per compendium PUT (embedded NPC portraits); other routes keep `MAX_BODY`.
- Copy from a book (R): a new id and the compendium's source, page 1, **no description** (book text never enters a compendium; the GM writes their own). NPCs (R): *moved* in (written into the compendium, then `DELETE /api/npcs/:id`, so the original sits in the NPC trash) and moved back out to edit; not edited in place. Both are client-side two-call moves; no new server routes.
- Server mode only (R): browser storage shows "Compendiums need the server" (like Campaigns/Trash).
- Export (R): a compendium exports as a `kind: "books"` file with one book (`exportBooks` over the GM's catalog, `npcs` = its NPCs), `source.compendium: true` (new optional v1 field; schema + doc), publisher = owner's name, descriptions always on (the GM's own text), no table rules.
- Chummer branch `feat/0.8.0` from origin/main; module branch `feat/0.6.0` from the module's origin/main after 0.5.0 is merged; the controller merges/releases. Never touch `public/data/*.xml`, `public/custom/`, `custom/`, `library/`, `.extract/private`; no book text in tests (made-up entries only); never kill processes by image name.
