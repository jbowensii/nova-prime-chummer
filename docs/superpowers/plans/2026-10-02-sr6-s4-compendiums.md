# SR6 S4 — SR6 compendiums Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GMs (admin, editors) on the Shadowrun 6 side make named compendiums of their own SR6 entries (qualities, weapons, armor, augmentations, electronics, gear, vehicles and drones, spells, rituals, adept powers, complex forms, metamagics, echoes, critter powers, critters, spirits, sprites, NPC stat blocks, lifestyles, contacts) plus their own SR6 NPCs, share them (private / an SR6 campaign's GMs / the table), browse the imported SR6 books as read-only compendiums, copy book entries in (no description), move SR6 NPCs in and out, and find the entries of every compendium they can read in their SR6 pickers, Game data and New NPC dialog. Exactly Anarchy's 0.8.0 compendiums, one game over, never mixed with Anarchy's.

**Architecture:** Reuse, not a copy. The server's `compendiumsApi` (server/compendiums.mjs) becomes game-parameterized and a second instance serves `/api/sr6/compendiums` from `characters/sr6/.compendiums/<owner>/<id>.xml` with the same rev/If-Match, sharing, trash, body cap, folder hooks and source-id guards, using SR6's campaigns and SR6's book sources. An SR6 compendium is one SR6 data-format file (`<sr6:data kind="compendium">`) whose children are ordinary SR6 entries (common.xsd's types, all citing the compendium's source) plus embedded `<sr6:character>` NPCs. The client lists the readable ones with a game-aware `compendiumStore.ts` and hands them to `loadSr6Catalog` as extra overlay files after the edits layer; `buildSr6Catalog` learns kind `compendium` (source origin `user`). The Anarchy page's list, details dialog, entry table and copy dialog become a game-agnostic shell; the SR6 page supplies only its entry rows and its entry form (split out of S1's edit dialog).

**Tech Stack:** as the repo already uses (TS/React/Vitest/Playwright/Node server, xmllint-wasm for XSD tests, no new dependencies). No Python in S4.

**Spec:** `docs/superpowers/specs/2026-10-02-sr6-ruleset-design.md` (§1 "Game separation", §2 storage and API, §4 "Compendiums", §5 export, §6 S4, §7). Builds on Anarchy's compendiums as shipped in 0.8.0 (`docs/superpowers/plans/2026-10-02-phase2-compendiums.md`, `.superpowers/sdd/2026-10-02-phase2-compendiums/final-review.md`: the source-id clash fixes) and SR6 S0–S3 as built (`.superpowers/sdd/sr6/*.md`). Rulings the spec left open are marked (R).

## Global Constraints

- Branch `feat/sr6` (ledger `.superpowers/sdd/sr6/progress.md`; no push and no tower04 install until the owner says so). Never touch `public/data/*.xml`, `public/custom/`, `custom/`, `library/`, `.extract/private` or `x/`. No book text and no book numbers in the repo or tests: made-up names and invented values only. Never kill processes by image name.
- Layout (R, S0's ruling one level down): `characters/sr6/.compendiums/<owner>/<id>.xml`, trash `characters/sr6/.compendiums/<owner>/.trash/<id>-<ms>.xml`, a deleted account's to `characters/sr6/.compendiums/.trash/<user>-…`. Backups include it as part of `characters/`. While a legacy account called `sr6` exists, `/api/sr6/compendiums*` answers 409 like every SR6 route and the folder is never touched.
- File (R): `<sr6:data xmlns:sr6="urn:chummer-sr6:data:1" kind="compendium" version="1" id="<12 hex>" name="…" source="<SOURCE_ID>" sharing="private|campaign|table" campaign="<12 hex, only for campaign>" rev="n" updatedAt="ISO">`; children in any order: entries of the compendium kinds (below) under their SR6 tags, each `source` = the compendium's, page ≥ 1, its own text in `<text>`; NPCs as `<sr6:character xmlns:sr6="urn:chummer-sr6:character:1" …>` exactly as `sr6ToXml` writes them (`<npc>` first). Schema `public/data/sr6/schema/compendium.xsd`. The owner is the folder, never the file.
- Compendium kinds (R): every SR6 kind but `priorities`, `metatypes`, `attributes`, `skills`, `lifemodules` and `rules` (those carry creation structure and rule numbers, not things a GM adds to a table). One list, `COMP_KINDS` in `src/sr6/engine/compendium.ts`, with each kind's attribute names and line parts as common.xsd declares them (a test reads common.xsd and fails on drift).
- API (R): `/api/sr6/compendiums` (GET list, PUT `/:id`, DELETE `/:id`), the shapes and rules of `/api/compendiums`. `need()` already gives it `editor` (scoped path). Read: owner; admin all; an editor `table` ones and `campaign` ones whose **SR6** campaign both they and the owner GM. Write/delete: owner only. Players 403 on every route. 20 MB PUT cap.
- Never cross games (R): each instance accepts only its own root (`ca2:data` in the Anarchy data namespace, `sr6:data` in SR6's, `kind="compendium"`), and refuses a body that names the other game's namespaces anywhere (`urn:chummer-sr6:` in an Anarchy compendium, `urn:chummer-anarchy2:` in an SR6 one: an embedded runner or entry from the other game). Campaign sharing checks that game's campaigns only. Listing, reading and the catalog overlay are per game: `/api/compendiums` never returns an SR6 file and `/api/sr6/compendiums` never an Anarchy one; neither catalog loads the other's.
- Source ids (R): `SOURCE_ID`, fixed after creation, unique **within the game**: across the SR6 book sources (`public/data/sr6/sources.xml`, `custom/sr6/imported/sources.xml`, `custom/sr6/sources.xml`, `custom/sr6/edits/sources.xml`, whichever exist) and every SR6 compendium (409). An Anarchy compendium and an SR6 one may share an id (the catalogs never meet). SR6 has no house sources yet, so books.mjs's `compendiumSources` guard stays Anarchy-only. The 0.8.0 review's guards carry over: a compendium whose source id later became a book's is skipped by the loader with an error, and its page opens as a banner with no Add, Edit, Copy-into or Move-in.
- Entry ids (R): `<source lowercased>.<slug>[-n]`, free in that kind's catalog map and in the compendium. New in S4 (closes 0.8.0's optional finding, SR6 only): a compendium entry whose id an entry of another source already holds in that kind is skipped with an error, never replacing the book's.
- Copy from a book (R): a new id, the compendium's source, page 1, attributes and line parts kept (they are stat values), `text` emptied, `edited`/`by` dropped. NPCs are *moved* (written into the compendium, then deleted from the SR6 NPC area into its trash; campaign sharing dropped) and moved back out under a new id to edit; client-side two-call moves, a failed second call undoes the first. No new server routes.
- Export (R): Foundry export of an SR6 compendium belongs to F1. S4 shows no Export button and only fixes the interface F1 reads: a compendium's catalog source is `{ id, name, publisher: owner's name, canon: false, origin: 'user', compendium: { id, owner } }`, and F1 adds `exportSr6Compendium(c, comp)` → one book with `source.compendium: true`, the entries' own text, its NPCs.
- Anarchy unchanged: every existing Vitest, Python and Playwright suite passes unchanged (`tests/server/compendiums.test.ts`, `e2e/compendiums.spec.ts`, `e2e/foundry.spec.ts` included). Anarchy files change only where named, each with no behaviour change on the Anarchy side beyond the foreign-namespace refusal.
- Vitest in `tests/sr6/`, `tests/ui/`, `tests/server/`; e2e `e2e/sr6-compendiums.spec.ts`.

## Review Focus

- One game can never read, save, share or load the other's compendium or embed the other's runner (Task 1 server tests + Task 8 isolation e2e).
- No book text enters a compendium: copy empties `text`; the SR6 book's private texts are never written by the page (Task 2 + Task 7 tests).
- A compendium never replaces a book's source or entry in anyone's catalog (Task 3 tests), and a compendium that didn't load can't be written through (Task 6).
- Players: 403 on the routes, no menu entry, no compendium entries in their SR6 catalog (Task 1, 4, 8).

## Rulings (R) summary
- Storage `characters/sr6/.compendiums/<owner>/` with S0's layout, trash and account hooks; `/api/sr6/compendiums` is a second instance of the same server code, not a copy.
- Each game's store takes only its own root and refuses a body naming the other game's namespaces; campaign sharing uses that game's campaigns; lists and catalogs never mix games.
- Compendium kinds: every SR6 kind but priorities, metatypes, attributes, skills, life modules and rules; fields and line parts come from one list kept equal to common.xsd by a test.
- Source ids unique within a game (books and compendiums), fixed after creation; 0.8.0's loader and page guards carry over; new for SR6: a compendium entry can't replace another source's entry with the same id.
- Copies keep stats (attributes, line parts), drop the description, cite the compendium page 1; NPCs move in and out (trash on the way in, new id on the way out); no new server routes.
- New entries are made with S1's entry fields (split out, line parts editable for beings and sprites); SR6 pickers get no Edit button, Game data links a compendium entry to its compendium for the owner.
- Load book NPCs ignores compendium sources.
- Export of an SR6 compendium is F1's (interface fixed here: the `origin: 'user'` + `compendium` source, `exportSr6Compendium` → one book with `source.compendium: true`).
